# AlarmMini — Node.js сервер

Об’єднання AIR-тривог за областями, MQTT, публічний HTTP API та локальна
панель налаштувань. Node-RED і база даних не потрібні.

Версія 1.4.0 додає карту областей, бічне меню, світлу й темну теми,
очищення журналу, статистику спостережень AIR та ресурси процесу/системи.
MQTT-топіки, коди 0–5, HTTP-відповіді й перевірка webhook збережені.

Версія 1.3.0 додала вкладку DuckDNS: перевірку IPv4, ручне й автоматичне
оновлення DNS, статус і журнал. Типово автоматичне оновлення вимкнено.

Версія 1.2.0 перевіряє публічний webhook перед кожною реєстрацією/оновленням.
Кнопка «Перевірити адресу» робить таку саму перевірку без зміни підписки.
Якщо Cloudflare блокує офіційний файл ключа, у панелі можна імпортувати PEM,
завантажений користувачем із офіційного посилання. Помилка перевірки адреси або
відсутність чинного ключа зупиняє реєстрацію до звернення до API підписок.

Версія 1.1.0 додає діагностику та журнал подій у локальній панелі:

- Час останньої спроби API, успішного отримання даних та фактичної зміни станів.
- З’єднання MQTT, зрозуміла причина помилки й час останнього надсилання карти.
- Останній вхідний webhook, останній запит із перевіреним підписом, лічильники
  прийнятих, відхилених та повторних подій. Реєстрація не прирівнюється до доставки.
- Журнал із 200 останніх записів у пам’яті, фільтр рівнів, пауза перегляду та
  автооновлення кожні 5 секунд. Лічильники та журнал починаються заново після
  перезапуску; це події застосунку, а не читання історичних файлів PM2.
- Окремі причини помилок ключа: HTTP-відповідь сервера, мережа, формат або запис
  на диск. Чинний ключ не замінюється, якщо оновлення не вдалося.

`GET /admin/api/diagnostics` потребує локальної адмін-сесії. Журнал не містить
токенів, паролів, URL із токенами або тіл webhook. Публічний формат 25 станів
та MQTT-топіки залишаються сумісними.

### Панель 1.4.0

- **Огляд:** карта з точним зіставленням 25 ключів регіонів, розподіл кодів
  0–5, свіжість API, MQTT і доставка webhook. Геометрія взята з наявної карти
  проєкту. Київ показує спільний стан міста й області, Севастополь — Криму.
  Штрихування означає частковий/змішаний стан, а не географічне покриття районів.
  Без першого знімка карта нейтральна; старий знімок має явне попередження.
- **Тривоги:** початки активного AIR (0 → 1–5), відбої (1–5 → 0), зміни
  карти, максимум одночасно активних регіонів, статистика по областях та до
  80 останніх переходів. Перший знімок і знімок після перерви довшої за
  `STALE_AFTER_MS` не створюють вигаданих початків/відбоїв. Статистика
  охоплює лише спостереження від запуску, не є історією офіційного API та
  не зберігається між перезапусками.
- **Ресурси:** CPU процесу (100% = одне ядро), RSS, heap, середня затримка
  event loop, пам’ять контейнера cgroup v2 або явно підписана пам’ять хоста,
  доступна квота CPU, load average хоста на Linux, вільне місце на файловій
  системі runtime. До 60 вимірювань раз на 10 секунд; графіки в пам’яті.
  Відсутність доступу до окремої метрики показується як «—»; збір статистики
  працює окремо від таймерів отримання/публікації тривог.
- **Журнал:** «Очистити журнал» очищає спільний буфер подій панелі для всіх
  адмін-сесій. Лічильники, останні успішні доставки, налаштування та файли
  PM2 не видаляються. `POST /admin/api/logs/clear` потребує локальної сесії,
  того самого origin і CSRF-токена. Нові події продовжують записуватися.
- **Підключення / DuckDNS:** ті самі операції реєстрації, перевірки адреси,
  імпорту ключа та оновлення DNS. Теми зберігаються лише в цьому браузері.

Нових пакетів, зовнішніх шрифтів, CDN або бази даних для панелі не потрібно.
`npm test` запускає тільки `test/*.test.js`, без повторного запуску копій із `dist`.

Покрокове перенесення з Windows у Debian LXC та автозапуск через PM2:
[DEPLOY.md](DEPLOY.md).

## Запуск

Node.js 22.16+. Виконувати з каталогу `server`:

```sh
npm ci
cp .env.example .env
# Заповнити .env
npm start
```

У PowerShell можна використати `Copy-Item .env.example .env`.
Основні параметри `.env`:

```dotenv
UKRAINEALARM_API_TOKEN=YOUR_UKRAINEALARM_TOKEN
HOST=0.0.0.0
PORT=3000
ADMIN_USERNAME=YOUR_LOGIN
ADMIN_PASSWORD="YOUR_PASSWORD"
PUBLIC_STATUS_TOKEN=YOUR_STATUS_TOKEN
WEBHOOK_TOKEN=YOUR_DIFFERENT_WEBHOOK_TOKEN
PUBLIC_BASE_URL=https://alarm.example.com
MQTT_URL=mqtt://YOUR_BROKER:1883
MQTT_USERNAME=
MQTT_PASSWORD=
```

`0.0.0.0` означає слухати доступні мережеві інтерфейси. Адреса конкретного
сервера не зашита в коді. Відкрий `http://LAN_ADDRESS:3000/` і введи логін
та пароль з `.env`. Для використання порту 80 без `:3000` зміни `PORT`;
операційна система має дозволяти процесу слухати цей порт.

Порожній `MQTT_URL=` вимикає MQTT. Сервіс не запускає MQTT-брокер.
Порожні `ADMIN_USERNAME` та `ADMIN_PASSWORD` вимикають можливість входу;
вбудованого пароля немає. Порожній публічний токен **вимикає** відповідний
endpoint із HTTP 503, а не відкриває доступ усім.

Згенерувати випадковий токен можна так; для статусу та webhook виконай двічі:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Паролі та токени беруться з `.env` або змінних середовища і не редагуються
через панель. Після їх зміни перезапусти процес.

## Налаштування в локальній панелі

1. Увійди за адресою сервера в локальній мережі.
2. У полі «Публічна адреса сервера» введи HTTPS-домен Cloudflare Tunnel,
   наприклад `https://alarm.example.com`, і натисни **Зберегти**.
3. Панель сформує посилання на `/public/status` та `/public/webhook`.
   Кнопки копіюють звичайне посилання або посилання з токеном.
4. Натисни **Перевірити адресу**. Сервер перевірить HTTPS/TLS, доставку POST
   через публічний домен, токен і те, що запит дійшов саме до цього екземпляра.
5. Натисни **Оновити ключ**. Якщо бачиш `WEBHOOK_KEY_CLOUDFLARE_CHALLENGE`,
   відкрий [офіційний PEM](https://api.ukrainealarm.com/webhook-public.pem)
   у звичайному браузері, пройди перевірку Cloudflare та збережи файл.
   Обери його в секції «Перевірка підпису» та натисни **Зберегти ключ із файлу**.
   Використовуй офіційний ключ, не власну пару RSA. Панель показує SHA-256
   публічного ключа у форматі SPKI DER для порівняння між серверами.
6. Натисни **Зареєструвати** для нової підписки або **Оновити** для чинної.
   Сервер повторить перевірку адреси; якщо ключа ще немає — спробує завантажити
   його автоматично. Лише після обох успішних кроків звернеться до API підписок.
7. Результат запиту та час останньої успішної дії з’являться на сторінці.

«Зареєструвати» виконує `POST /api/v3/webhook`, «Оновити» — `PATCH`,
«Відписатися» — `DELETE`. Запити йдуть із сервера до UkraineAlarm з його
API-токеном. JSON-тіло: `{"webHookUrl":"HTTPS_URL/public/webhook?token=..."}`.
Токен UkraineAlarm і пароль адміністратора не передаються в JavaScript сторінки.
Підписка не реєструється автоматично при старті чи збереженні адреси.

Перевірка адреси використовує одноразовий випадковий запит зі строком дії
до `REQUEST_TIMEOUT_MS`: POST на точний URL із токеном і заголовком
`X-AlarmMini-Probe`. Успіх потребує підтвердження в пам’яті поточного процесу та
окремої випадкової відповіді. Відповідь іншого сервера, просте віддзеркалення,
редирект або прострочений запит не проходять. Тест не змінює карту, не опитує
UkraineAlarm і не зараховується як реальний webhook. Доставка від UkraineAlarm
підтверджується окремо, лише після справжньої події з правильним підписом.
Використовуй один екземпляр PM2: перевірка навмисно виявляє неправильний
сервер/порт, а також маршрутизацію на інший процес.

Відписка використовує останню зареєстровану адресу, навіть якщо публічний
домен у формі вже змінено. Якщо сервіс ще не має запису про наявну зовнішню
підписку, для її зміни використай **Оновити**. API не має GET-методу читання
підписки: індикатор у панелі показує останню успішну дію цього сервера.

Збережений домен і результат реєстрації зберігаються в `runtime/settings.json`
та переживають рестарт. Збережений у панелі домен має пріоритет над початковим
`PUBLIC_BASE_URL` з `.env`. URL чинної підписки містить webhook-токен;
каталог `runtime` виключено з Git і Docker build. Логін/пароль там не зберігаються.
Сесії входу живуть лише в пам’яті до 8 годин; рестарт завершує їх.

## DuckDNS

У локальній панелі відкрий вкладку **DuckDNS**. Введи назву вже створеного
піддомену (коротку або повну) й токен акаунта. Поле IPv4 можна залишити порожнім:
тоді сервер визначає власну зовнішню IPv4 через `https://api.ipify.org`.
Якщо MQTT-брокер в іншій мережі, введи його публічну IPv4 вручну.

1. Збережи налаштування. Порожнє поле токена зберігає попередній секрет;
   для видалення є окремий прапорець (спочатку вимкни автоматичне оновлення).
2. **Перевірити без змін** порівнює потрібну IPv4 з A-записом домену.
   Ця дія не надсилає токен у DuckDNS і не перевіряє його правильність.
3. **Оновити зараз** надсилає запит у DuckDNS навіть при збігу адрес.
   Лише відповідь `OK` з правильною IPv4 та `UPDATED`/`NOCHANGE` підтверджує запит.
4. Для фонового режиму ввімкни **Автоматично оновлювати IPv4** і збережи.
   Перша перевірка виконується одразу після збереження або запуску сервера;
   наступні — кожні 5 хвилин типово (доступно 1–1440 хвилин).
   При збігу адрес запит оновлення не надсилається. Збої повторюються за тим самим
   розкладом; паралельні операції блокуються. Сторінку можна закрити.

Налаштування з панелі мають пріоритет над початковими `DUCKDNS_*` із `.env`.
Вони зберігаються у `duckdns.json` поруч із `SETTINGS_FILE` (типово
`runtime/duckdns.json`), з правами `0600` на Linux. Токен не повертається в API
панелі й не потрапляє в журнал. Зберігай цей файл разом із `.env` під час оновлень.
Поточні результати й час перевірок зберігаються в пам’яті до перезапуску або
зміни домену, IP чи токена. Журнал подій спільний для обох вкладок.

Панель показує потрібний IPv4, останню DNS-відповідь, час перевірки, прийнятого
запиту, фактичної зміни за відповіддю DuckDNS та наступну перевірку. Підтвердження
API не означає, що всі DNS-кеші вже оновилися. Відсутність A-запису можна виправити
оновленням; помилка DNS, ipify, некоректна відповідь або таймаут не показуються як успіх.

Адмін-маршрути (локальний доступ, сесія; для змін також CSRF):

| Метод і шлях | Дія |
|---|---|
| `GET /admin/api/duckdns` | Налаштування без токена й останній результат |
| `PUT /admin/api/duckdns` | Зберегти `enabled`, `domain`, `token`, `ipv4`, `intervalMinutes`; необов’язково `clearToken` |
| `POST /admin/api/duckdns/check` | Перевірити без зміни DNS |
| `POST /admin/api/duckdns/update` | Оновити зараз |

Змінюється лише IPv4; існуючий IPv6-запис не змінюється. Домен не створюється
і не видаляється. Вимкни інший updater, якщо він може записувати інший IP.
Це DDNS-оновлення, а не перевірка доступності MQTT чи перемикання на резерв:
коли цей сервер вимкнений, він не може оновлювати DuckDNS. NAT/CGNAT і відкриття
портів цей механізм також не змінює.

Джерела: [DuckDNS API](https://www.duckdns.org/spec.jsp),
[ipify IPv4 API](https://www.ipify.org/).

## Cloudflare Tunnel

Налаштуй published application route:

| Поле | Значення |
|---|---|
| Hostname | Твій публічний домен |
| Path | `^/public/.*$` |
| Service URL | `http://LAN_ADDRESS:3000` |

У Service URL не додавай `/public`. Cloudflare передає повний початковий
шлях: `/public/status` доходить до Node.js саме як `/public/status`.
Див. [правила шляхів Cloudflare](https://developers.cloudflare.com/tunnel/advanced/local-management/configuration-file/).

Для решти шляхів цього hostname залиш відповідь 404, без іншого правила,
яке публікує всю локальну панель. Додатково сервер відхиляє адміністративні
запити через публічний Host або заголовки проксі/Cloudflare.
Для `/public/*` потрібна можливість звичайного HTTP-запиту без інтерактивного
входу Cloudflare Access чи браузерної challenge-сторінки: токен перевіряє Node.js,
а webhook також має криптографічний підпис.

Адміністративні сторінки доступні напряму через loopback або приватну LAN-адресу.
Для локального DNS-імені додай його без порту в `ADMIN_ALLOWED_HOSTS`, наприклад
`ADMIN_ALLOWED_HOSTS=alarmmini.local`. Ця опція не дозволяє адміністрування
через публічний проксі. Пароль при прямому HTTP-вході передається всередині
локальної мережі без TLS; використовуй таку панель у довіреній LAN.

## Публічний статус

`GET /public/status` повертає масив рівно з 25 чисел. Авторизація на вибір:

```http
GET /public/status
Authorization: Bearer YOUR_STATUS_TOKEN
```

Або посилання для браузера:

```text
https://alarm.example.com/public/status?token=YOUR_STATUS_TOKEN
```

Значення query-токена має бути URL-кодоване; панель робить це автоматично.
Якщо присутній заголовок Authorization, перевіряється саме він.
Неправильний/відсутній токен повертає 401; незаданий у `.env` — 503.
Query-токен може потрапити в історію браузера чи журнали проксі, тому для
пристрою краще використовувати Bearer-заголовок.

У резервний канал прошивки **2.1.0+** запиши HTTPS-адресу `/public/status`
та `PUBLIC_STATUS_TOKEN` у поле токена, без слова Bearer.
До першого коректного знімка і через 90 секунд без нових даних endpoint
повертає **503**, а не масив нулів. Відповідь 200 не стискається і не кешується;
масив із 25 кодів 0–5 займає 51 байт.

Локальні `/alerts` та `/api/status` залишені для сумісності: перший віддає
масив, другий — розширений стан із `fresh` і часом. Вони також вимагають
токен статусу. Попередня змінна `HTTP_API_TOKEN` підтримується як запасна
назва, якщо `PUBLIC_STATUS_TOKEN` не заданий. `/health` доступний локально
без токена: 200, якщо дані свіжі й MQTT підключений або вимкнений, інакше 503.

## Вхідний webhook

```text
POST https://alarm.example.com/public/webhook?token=YOUR_WEBHOOK_TOKEN
```

Потрібні **окремий webhook-токен і підпис UkraineAlarm**. Підпис RSA-SHA256
перевіряється над точними байтами `{timestamp}.{raw_request_body}`, з допуском
часу ±5 хвилин і відхиленням повторних подій. Синхронізуй годинник сервера.
Статус 202 означає прийняття події для оновлення, а не завершений запит API.

Публічний ключ зберігається у `runtime/webhook-public.pem`; кнопка «Оновити ключ»
оновлює його без перезапуску. Для вручну керованого файла можна встановити
`WEBHOOK_PUBLIC_KEY_FILE`; тоді перевір, що він доступний процесу, а для
оновлення через панель — також доступний для запису. Без ключа реальні webhook
отримують 503. Автоматичне завантаження ключа використовує лише фіксовану
офіційну адресу UkraineAlarm. Імпорт через `PUT /admin/api/webhook-key`
потребує локальної адмін-сесії та CSRF; приватні ключі та HTML відхиляються.
`POST /admin/api/webhook-check` також потребує адмін-сесії та CSRF.

Подія запускає повний `GET /alerts`: запізнілий відбій одного району не
очищує інші райони. Одночасні події об’єднуються; запити не перекриваються
і починаються не частіше ніж раз на 5 секунд. Планове опитування раз на
30 секунд працює незалежно від webhook. `Retry-After` для 429/503 має пріоритет.

## Кольори, MQTT і дані

| Код | Значення |
|---:|---|
| 0 | Немає активних AIR-рівнів в області |
| 1 | Червона повітряна тривога на всю область; оранжевого немає |
| 2 | Оранжевий рівень на всю область; червоного немає |
| 3 | Будь-яке одночасне поєднання червоного й оранжевого в області |
| 4 | Частково червона область; оранжевого немає |
| 5 | Частково оранжева область; червоного немає |

Оранжевому відповідає **`Yellow`** у UkraineAlarm, червоному — `Red`.
Враховуються лише активні рівні `AIR` в областях, районах, громадах і населених
пунктах. **Стан 3 має пріоритет** навіть для двох часткових тривог або червоної
всієї області з оранжевим в одній громаді. Порядок записів і повтори не впливають.

«Вся область» означає активний рівень для ID самої області (`stateId` у
`data/regions.json`, область типу `State`). Записи лише для її дочірніх регіонів
дають частковий стан, навіть якщо їх багато; повне покриття громадами не
обчислюється. Використовується ID конкретної тривоги, а не її контейнера у відповіді.
Київ і Київщина — одна позиція: тривога лише для міста Київ (`31`) часткова,
для Київської області (`14`) — загальнообласна.

Наприклад: червона область + оранжева громада → `3`; після відбою оранжевого →
`1`; якщо загальнообласний червоний скасували, але він залишився в районі → `4`.
Кожен повний знімок API обчислюється заново. Порожній список рівнів не скасовує
активні рівні інших записів.

Для старого активного AIR без поля рівнів або з `null` використовується червоний.
Невідомий колір, некоректна структура чи нерозпізнаний активний ID відхиляє
весь знімок, зберігаючи попередні дані.

| MQTT-топік | Дані |
|---|---|
| `ukraine/alarm/map/full` | Старий масив 0/1, усі активні стани 1–5 стають 1 |
| `ukraine/alarm/map/full_v2` | Масив кодів 0–5 |
| `ukraine/alarm/map/status` | starting / online / stale / offline |

Повідомлення мають retain=true, QoS 0 і повторюються після кожного успішного
опитування як сигнал свіжості для прошивки. Після перепідключення MQTT
надсилається лише ще свіжий останній знімок; старі повідомлення не накопичуються.
На прошивці **2.1.0+** обери `full_v2`, додай коди **2, 3, 4, 5** та налаштуй
їхні денні й нічні кольори. Коду **1** задай червоний, **2** — оранжевий.
Без власної палітри додатковий код використовує колір стану 1. Поточна прошивка
показує кожен додатковий стан одним постійним кольором: код 3 сам по собі не
вмикає чергування червоного й оранжевого. У локальній панелі сервер показує
змішаний стан двома кольорами, часткові — частковим заповненням, усі — з кодом.
Перед публікацією в чинні топіки зупини відповідний Node-RED flow.

У `data/regions.json` перенесено 25 груп і 1605 ID з початкового flow.
Порядок відповідає [контракту прошивки](../docs/http-fallback.md).
Дерево `/regions` доповнює таблицю після першого успішного опитування,
раз на добу і при появі невідомого активного ID. Зміни дерева зберігаються
в пам’яті та завантажуються знову після рестарту.

Помилки не перетворюються на відбій. Через 90 секунд дані позначаються
застарілими, HTTP повертає 503, а retained-масиви видаляються порожніми
повідомленнями, які прошивка відхиляє. При штатному завершенні вони також
видаляються. При аварії Last Will позначає status=offline, але останній
retained-масив може залишитися: MQTT 3.1.1 не має часу придатності, а поточна
прошивка не читає status-топік. Новий підписник може короткочасно вважати
цю копію свіжою. Після запуску сервіс видаляє або оновлює її.
HTTP резервує транспорт MQTT, але використовує той самий процес і UkraineAlarm API.

## Docker

```sh
docker compose up -d --build
docker compose logs -f
```

Compose публікує порт на `HTTP_BIND` і `HTTP_PORT` з `.env` (за замовчуванням
0.0.0.0 та 3000). Це дозволяє LAN-доступ і підключення cloudflared з іншого
комп’ютера. `runtime` зберігається в Docker volume `alarmmini-runtime`.
Не видаляй volume, якщо хочеш зберегти налаштування. `.env` не вбудовується в образ.
У `MQTT_URL` вкажи адресу, доступну контейнеру: його localhost — сам контейнер.
При контейнерному запуску внутрішній `PORT` лишається 3000; зовнішній змінюй
через `HTTP_PORT`.
