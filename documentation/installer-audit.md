# Аудит вебінсталятора AlarmMini — 2026-09-07

## Зміни

- Основний сценарій: вибір плати → USB → запис. За замовчуванням обране оновлення зі збереженням конфігурації. Для першого встановлення потрібне окреме підтвердження стирання.
- MQTT, JSON, QR-коди, файли й журнал перенесено в згорнуті додаткові налаштування. Є пояснення щодо кабелю, COM-порту, BOOT, Wi-Fi 2,4 ГГц і повторної спроби.
- Непідтримуваний браузер отримує інструкцію використати Chrome/Edge на комп’ютері; прошивання заблоковане.
- Старий виклик `connect()` ESP Web Tools повертався після відкриття діалогу. Тепер завершення підтверджується фактичним `finished` від `flash()`; помилка бібліотеки, навіть якщо її Promise успішно завершився, зупиняє відновлення.
- Помилка читання конфігурації не перемикає інсталятор на стирання і не дозволяє використати стару браузерну копію автоматично. Перед записом потрібна свіжа валідна копія підключеної плати.
- Відновлення записує всю конфігурацію однією транзакцією та порівнює результат. Розбіжності більше не перекриваються повідомленням про успіх. Відновлення після помилки перевіряє hostname плати поточної спроби.
- Повторне підключення використовує вибраний порт, без автоматичного вибору першого стороннього дозволеного порту. Скасування діалогу й від’єднання USB обробляються явно.
- Додано захист від подвійного запуску та випадкового закриття вкладки під час запису, фокус у модальному редакторі, приховане введення паролів, індикатор фактичного прогресу.
- Стабільні релізи завантажуються через серверний кеш із повторною спробою. Редактор конфігурації завантажується окремо.
- Оновлено Next.js у межах 15.5, сумісні залежності та PostCSS. Версію ESP Web Tools зафіксовано на перевіреній 10.2.1.

## Перевірка

- `npm run build`: успішно, Next.js 15.5.25.
- TypeScript: без помилок.
- 7 тестів функції запису: фактичне завершення, помилки ініціалізації/моделі/завантаження/запису, відсутній фінальний стан, перше встановлення.
- 7 браузерних тестів на production-збірці в Edge: безпечні початкові значення, підтвердження стирання, відсутній Web Serial, скасування USB, повторне завантаження релізів, вузький екран, відсутні файли плати, відмова від старої копії після помилки нового читання.
- Візуально перевірено настільний і мобільний інтерфейс (390 px). Браузерні перевірки не виявили необроблених JavaScript-помилок у перевірених сценаріях.
- Усі 7 опублікованих `.bin` релізу v2.0.5 отримані через локальний `/api/release-asset`: HTTP 200, розміри збігаються з GitHub.
- `npm audit --omit=dev`: 0 відомих вразливостей на момент перевірки.
- Фізичний запис через браузер у цьому аудиті не виконувався; USB у браузерних тестах імітується. Це не замінює перевірку кабелів, BOOT і повторного визначення порту на реальному обладнанні.

## Публікація

Підготовлена версія інсталятора: 2.0.7. Production-запит до наявного проєкту Vercel відхилено з HTTP 403: поточний доступ не дозволяє створити Production Deployment. Локальна CLI-авторизація також недійсна. Потрібен вхід власника проєкту через `npx vercel login`, після чого можна виконати `npx vercel deploy --prod --yes` з папки `vercel` і перевірити публічний сайт.

Публікація сайту не публікує змінені локальні прошивки: доступний через інсталятор реліз залишається GitHub v2.0.5, доки не буде створено новий firmware release.
